# 1.0.2 任务路由与澄清修复

## 实测基线

用户于2026-11-17运行真实Qwen评测，终端截图显示开发分区27/30、验证分区19/20，总计46/50。开发用量23729 Token、57.261秒；验证用量15793 Token、40.538秒。

失败为C04、C09、B01和C07，均停在条件提取的业务支持判断。此前并未记录模型原始工具参数，因此不能从旧日志确认supported的具体返回值；对代码路径注入supported=false可以复现同样错误。

## 修复

- supported描述业务能力而非参数完整性。已知金额/发票均值任务缺口径、缺时间、无效时间、相对日期应进入澄清流程。
- 程序依据能力契约判断已知任务，避免模型单个拒绝标记直接跳过后续参数检查。
- 区间工具仅处理正向商品发票金额均值，不把净额/转化率区间等其他统计对象强行映射过来。
- 退款到账、利润、预测、因果、显著性等不支持任务仍拦截；额外锚定发票号与国家，显式筛选无法确认时停止，避免丢失筛选而汇总全量。
- 新日志保存模型原始工具参数、程序应用的参数和实际会话条件，可在一个评测JSON中查看拒绝与提取差异。不记录鉴权头或.env内容。
- 不改数据库、指标公式、原50题标准答案；原50题文件与初始交付ZIP逐字节一致。

## 安装与复测

停止Streamlit，将补丁内容覆盖到现有项目根目录。无需安装依赖或重建数据。

推荐一次运行 `python accept_release.py`。它先运行自动检查，再按4题故障复测、50题回归、新20题顺序调用真实API；任何阶段失败会停止后续阶段，并保存一份汇总JSON。合计最多74题请求，连接建立失败可能额外重试；分阶段记录通过率与用量，不把重复用例合并成独立样本。

```powershell
# 本机自动检查
.\.venv\Scripts\python.exe -m pytest -q

# 先复测四个已知失败；这是回归测试
.\.venv\Scripts\python.exe .\evaluate_real.py --mode live --split all --ids C04 C09 C07 B01 --limit 4

# 四题通过后，运行新冻结的20条措辞检查
.\.venv\Scripts\python.exe .\evaluate_real.py --suite release_check --mode live --split validation --limit 20
```

这50题已经用于本次故障定位，后续通过率按回归结果记录，不再称作未用于调试的验证成绩。新20题也只是有限范围的措辞检查；若据其失败调试，该版本后续复跑应作为回归，不能声称广泛泛化准确率。

用户已在 Windows 完成 v1.0.2 真实 API 验收：故障复测 4/4、原 50 题回归 50/50、新 20 题措辞检查 20/20。该状态来自终端截图，原始汇总 JSON 待附件核对。用量和适用范围见 `实测验收记录.md`；云端模拟检查仍单独登记。

命令中的--ids只选择指定用例；--suite默认regression，指原50题，release_check指新增20题。所有评测每题新建会话，报告保存于reports目录。
