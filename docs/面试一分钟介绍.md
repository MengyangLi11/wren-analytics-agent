# 面试一分钟介绍

我做了一个可核验的零售数据分析 Agent，基于 Wren Engine、LangGraph 和 Qwen Function Calling。数据来自 UCI Online Retail，原始有 54.19 万行，按明确口径纳入 53.64 万行。

它的重点是让结果有计算依据。模型负责提取指标、时间、发票和国家条件；程序保留多轮状态，缺信息就追问，用户确认后再执行固定 SQL。金额通过 Decimal 与数据库对账，报告附有口径版本、原始行号、SQL 和数据指纹，还能从 JSON 证据重算。

结合数学背景，我增加了客户簇 Bootstrap。先聚合发票，再按客户重采样，保留同一客户多次购买的关联；同时明确样本排除规则和推断假设。

评测方面，修复任务路由后，原 50 条真实 API 回归由 46 条通过变成全部通过，新 20 条措辞检查也全部通过。这个结果只代表固定测试范围；同集 Token 增加约 14.8%，是这次可靠性改进的用量代价。

## 面试官追问时可展开的三个实例

1. “收入多少？”不能直接默认成净额：先澄清指标及时间；缺参数和不支持任务分开判断。
2. C 发票只是取消记录，不能当作到账退款；缺少原订单关联依据时不擅自配对。
3. Bootstrap 每轮用客户簇的总金额除以总发票数，避免把发票加权均值误做成客户均值的简单平均。
